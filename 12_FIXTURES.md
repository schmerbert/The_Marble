# Fixtures

A room gives the Resident a field of attention. A fixture gives that attention somewhere to land.

The shelves invite looking through material. The workbench holds proposed cuts. The kiln carries a bounded process while it runs. The ledger shows history; the clipboard holds the brief. Each is an installed, place-bound affordance with a name the Resident can return to. A fixture may present state, accept an action, or hold work in progress. Its physical metaphor should help predict the action it supports.

## The Workshop's surfaces

In the Hub's Workshop, five fixtures divide the work without dividing the room into five rooms:

| Fixture | Work gathered there | What inspection reveals |
| --- | --- | --- |
| Shelves | Explore the repository | A bounded root listing |
| Workbench | Change files and handle proposed cuts | Pending approvals |
| Kiln | Run named recipes | Its current run or honest idle state |
| Ledger | Inspect and land Git history | A bounded branch and change digest |
| Clipboard | Keep the current job in view | The session brief |

The list is an example of a coherent arrangement, not a required kit for every Marble. A smaller room may need only one fixture. A fixture earns its place when it gives a function a stable location and a useful way to inspect what is happening there.

## Reach and focus

Four things should remain distinct:

1. The **Ceiling** knows which capabilities are installed.
2. The **room mount** determines which of those capabilities are lawful at the current location.
3. The **fixture** gives related work a local face and may hold or project its state.
4. The **current hand** is the smaller set of actions presented to the Resident now.

In the Hub, the Workshop mounts its full catalog while the Resident is there. Inspecting a fixture returns a bounded account of its contents without changing focus. Engaging one brings it into working focus and fits its related action schemas to the next provider continuation. Engaging another transfers focus directly; leaving the Workshop clears it. This saves context and gives the Resident a legible way to choose its tools. Engagement does not grant a new permission: the gateway still checks the room's mounted law when an action is called.

This distinction lets a fixture *house a function* in the Resident's experience without pretending that the furniture is the source of authority. A workbench can be the place where a proposed cut waits for approval. The approval's standing, custody, and enforcement still need explicit machinery and a receipt. Turning toward the workbench cannot approve the cut by itself.

## The fixture's contract

For each fixture, a builder should be able to answer:

- **Where is it?** Its installed place and whether the Resident can inspect or engage it there.
- **What does it provide?** The actions and bounded view associated with it.
- **What does it require?** Room mounts, source material, state, or another installed organ.
- **What does it own?** Any durable or living state for which this fixture is the proper anchor.
- **What can it change?** The exact effects of an action and where those effects are recorded.

The answers should be visible enough that the Resident can tell whether a surface is ready, busy, empty, or refusing a request. A running kiln should report its run; a quiet kiln should say it is idle. A shelf should disclose that a listing is truncated. The room's presence can name the fixtures and their salient state without sending a full tool catalog on every turn.

Fixtures make complexity graspable when their names and behavior agree. If the Resident must learn a hidden rule to use one, the fixture has not yet earned its shape.
